# اگر چند ماه بعد به پروژه برگشتم

این پروژه دو کار اصلی داشت: ساخت زیرمجموعه نسخه پنج از IADD، و آموزش تکمیلی مدل ازپیش‌آموزش‌دیده YOLO11s برای تشخیص شش رده. رده «شخص» فقط عابر نیست؛ «خودروی باری» هم وانت و کامیون را شامل می‌شود.

## از کجا شروع کنم؟

| چیزی که می‌خواهم یادم بیاید | فایل یا پوشه |
|---|---|
| منطق ساخت نسخه پنج | `code/build_subset_v5.py` |
| عضویت دقیق هر تصویر و ویدیو در بخش‌ها | `dataset manifests/` |
| آمار تصاویر، نمونه‌ها، اندازه اشیا و شرایط محیطی | `code/compute_v5_validity.py` و `figure and table data/stats.json` |
| اجرای واقعی آموزش نهایی | `code/IADD_YOLOv11_Colab_run8.ipynb` |
| تنظیمات واقعی ذخیره‌شده در وزن | `models/run8-metadata.json` |
| چرا رکوردها بررسی و حذف شدند؟ | `record review/`، کدهای audit و خروجی‌های تاریخی |
| نمودارها چطور ساخته شدند؟ | `code/make_figures_ch2.py` و `code/make_figures_ch3.py`؛ نقشه منابع در `docs/FIGURES.md` |
| رسم برچسب واقعی و پیش‌بینی روی عکس | `code/demo_boxes.py` |
| ارزیابی جدید مدل | `code/evaluate.py` |
| پایان‌نامه و ارائه نهایی | `presentation and thesis/thesis.docx` و `presentation.pptx` |
| آموزش معماری و توضیحات دفاع | `docs/study-guides/` |

## تصمیم‌هایی که نباید فراموش شوند

- بخش آزمون اولیه IADD در نسخه دانلودشده برچسب نداشت. آزمون پروژه ما از داده‌های دارای برچسب ساخته شد؛ همه داده‌ها دوباره برچسب‌گذاری نشدند.
- تقسیم در سطح ویدیو انجام شد؛ فریم‌های یک ویدیو میان بخش‌های پروژه پخش نشدند. تکراری‌های دارای نام متفاوت نیز جداگانه کنار گذاشته شدند.
- رکوردهای دارای برچسب مشکل‌دار: `Record426_D` و `Record046_D`.
- نسخه‌های کنارگذاشته‌شده تکراری: `407_D` در برابر `409_D`، `416_R` در برابر `438_R` و `043_D` در برابر `042_D`.
- سازنده داده ابتدا سهم نمونه‌های رده‌های منتخب را در هر شرایط محیطی دنبال می‌کند؛ برای ویدیوهای بدون آن رده‌ها، کمبود تعداد فریم را ملاک قرار می‌دهد. سپس نمونه‌برداری درون هر بخش انجام می‌شود. توازن اندازه اشیا مستقیماً هدف این الگوریتم نیست.
- نسخه نهایی: ۳۷٬۱۴۲ تصویر، ۲۷۵٬۸۱۳ نمونه و ۱۶۰ ویدیوی دارای فریم منتخب. سهم ۷۰/۱۵/۱۵ مربوط به تصاویر است.
- مدل نهایی، وزن اجرای اصلی run8 است. اجرای اصلی AdamW داشت؛ مرحله ده‌دوره‌ای تکمیلی واقعاً SGD داشت و برنده نشد. نسخه‌های ویرایش‌شده برای دفاع را با تنظیمات اجرای واقعی اشتباه نکنم.
- آستانه ۰٫۴۰۶ از نمودار F1 اعتبارسنجی انتخاب شد. محاسبه منحنی‌های AP با ارزیابی محدود به همین آستانه یکی نیست.
- اندازه‌های کوچک، متوسط و بزرگ براساس مساحت نسبی کادر تعریف شدند: کمتر از ۱٪، از ۱٪ تا کمتر از ۶٪ و دست‌کم ۶٪ تصویر.
- در ماتریس: سطرها پیش‌بینی و ستون‌ها حقیقت هستند؛ سطر آخر اشیای ازدست‌رفته و ستون آخر تشخیص‌های بدون تطبیق را نشان می‌دهد. خانه پس‌زمینه/پس‌زمینه TN معمول رده‌بندی نیست.

## چه چیزی فقط در GitHub نیست؟

تصاویر کامل دیتاست و وزن‌های کامل دارای وضعیت بهینه‌ساز داخل مخزن عمومی نیستند. لینک Drive در README آمده؛ پوشه آن فایل `iadd_subset_v5.zip` را نشان می‌دهد، اما سلامت و محتوای کامل ZIP باید پیش از حذف دیتاست محلی بررسی شود.

پشتیبان‌های خصوصی داخل پوشه جداگانه `project-archive-backups/2026-10-08` روی دسکتاپ هستند: نسخه قبلی مخزن، وزن‌های کامل آموزش، برچسب‌های نسخه پنج و PDFهای موجود. بهتر است آن پوشه نیز روی Drive یا حافظه دیگری نگهداری شود. وزن `models/run8_best.pt` برای اجرای مدل کافی است، ولی ادامه همان جلسه آموزش را ممکن نمی‌کند.

برای بازسازی دقیق مجموعه داده، فهرست ثبت‌شده و `restore_v5_from_manifest.py` را استفاده کنم. اجرای دوباره الگوریتم روی پوشه‌هایی که نامشان بعداً تغییر کرده، تضمین نمی‌کند همان تصاویر تاریخی انتخاب شوند.
